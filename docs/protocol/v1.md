# Eat TCP Protocol v1

## 1. 传输与分帧

- 传输：TCP，应用层自建帧协议。
- 编码：JSON，UTf-8，无 BOM。唯一编码，不设编码类型位，不允许 Protobuf/MessagePack/CBOR。
- 帧：40 字节定长头（大端）+ JSON body。
- 最大帧：`max_frame_size` 默认 65536，硬顶 262144。
- 校验：CRC32C 覆盖 `header[0..35] || body`，不含 checksum 字段自身。

## 2. 帧头字段

| 偏移 | 宽度 | 字段 | 约束 |
|---|---|---|---|
| 0 | 4 | magic | 固定 `EAT1` |
| 4 | 1 | ver_major | 当前 1 |
| 5 | 1 | ver_minor | 当前 0，必须落在支持窗口 |
| 6 | 1 | frame_type | 0x01–0x09 |
| 7 | 1 | flags | 仅 bit3 urgent（仅 close 允许），其余必须 0 |
| 8 | 1 | header_len | 固定 40 |
| 9 | 1 | reserved0 | 必须 0 |
| 10 | 4 | body_len | ≤ max_frame_size |
| 14 | 8 | request_id | 客户端单调递增，响应原样回带 |
| 22 | 8 | seq | 推送/事件序号，请求/响应/心跳填 0 |
| 30 | 4 | error_code | 成功为 0 |
| 34 | 2 | reserved1 | 必须 0 |
| 36 | 4 | checksum | CRC32C |

## 3. 帧类型

| 值 | 名称 | 方向 | body |
|---|---|---|---|
| 0x01 | handshake_req | C→S | 对象 |
| 0x02 | handshake_resp | S→C | 对象 |
| 0x03 | request | C→S | 对象（method + params） |
| 0x04 | response | S→C | 对象（ok + data/error） |
| 0x05 | heartbeat | C→S | 空或 `{}` |
| 0x06 | heartbeat_ack | S→C | `{}` |
| 0x07 | push | S→C | 对象，≤1024B |
| 0x08 | close | S→C | reason + retry_after_ms |
| 0x09 | error | S→C | code + message + reason |

不存在 `llm_proxy` 或 `llm_stream_*` 帧；LLM 增量只在客户端本地通过 HTTPS/SSE 消费。

## 4. 粘包 / 半包 / 拆包

1. 读缓冲按已消费偏移滑动，不使用整段字符串重新查找。
2. 读满 40 字节头后校验 magic/版本/类型/flags/header_len/body_len；`body_len` 超限必须在读 body 前拒绝。
3. 读不满 body 返回半包等待，上层 5 秒超时后按 `frame_wait_timeout` 断连。
4. 粘包循环切分，单次读取最多处理 64 帧后让出。
5. 非法 magic/版本/类型/flags/头长/校验失败：返回对应错误码并断连。
6. request/response 的 `body_len=0` 视为 `invalid_json:syntax`；heartbeat/heartbeat_ack/close/error 允许空 body。

## 5. 握手与版本协商

1. 连接建立后首个有效帧必须是 `handshake_req`；否则 `2001 handshake_required` 并断连。
2. 握手阶段禁止 Redis 读写。
3. 版本：`client.major == server.major` 且 `client.minor >= min_supported_minor` 且 `client.minor <= server.minor`。
4. 能力位取交集：`push`、`pull_sync`、`meal_edit`、`friend_write`、`idem_v1`、`tls_resume`。
5. 握手成功下发 `heartbeat_interval_s=60`、`idle_timeout_s=165`、`max_frame_size`、版本与能力。

## 6. 心跳与超时

| 项 | 值 |
|---|---|
| 心跳周期 | 60s（验收基线） |
| 空闲超时 | 165s（150–180 可配） |
| 半包等待 | 5s |
| 业务请求超时 | 3s |
| 重连退避 | 1s 起，指数翻倍，上限 30s，±20% 抖动 |

心跳路径必须零 MySQL、零 Redis、不进业务队列。

## 7. 错误码

| 段 | 范围 | 说明 |
|---|---|---|
| 帧 | 1001–1009 | magic/版本/类型/flags/头/超长/校验/JSON/半包 |
| 鉴权 | 2001–2008 | 握手/未授权/过期/越权/禁用/顶替/失败冷却/refresh 重用 |
| 业务 | 3001–3005 | 参数/用户不存在/幂等冲突/不存在/版本冲突 |
| 资源 | 4001–4005 | 限流/过载/连接上限/慢消费者/请求超时 |
| 依赖 | 5001–5004 | 服务不可用/缓存不可用/内部错误/跳数超限 |
| 关闭 | 9001–9004 | 服务关闭/被顶替/空闲/协议错误 |

`error_code` 与 body 内 `error.code` 双写。

## 8. 业务方法

`auth.*`、`profile.*`、`meal.*`、`stats.*`、`food.*`、`friend.*`、`ranking.*`、`sync.*`。

写操作必须在 `params` 内携带 `idem_key`。业务身份只取握手绑定的 `user_key`，body 内的 `user_id`/`user_key` 一律忽略并计数。

## 9. 关闭

服务端主动关闭必须先发送 `close` 帧（含 reason 与 retry_after_ms），再 drain 发送队列，最后关闭连接。禁止静默丢弃或直接 RST（异常场景除外）。
