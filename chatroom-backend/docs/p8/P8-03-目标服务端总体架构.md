# P8-03 目标服务端总体架构（P8-2 修订版）

> 设计原则：前端与 Agent 是既定契约；C++ 以**最小成本、最小侵入**适配。
> 基于现有 P7 代码结构（TcpServer/Reactor/Connection/ChatService/MySQLPool/Redis）落地，不画不可实现的图。

## 1. 架构决策总览

| 决策点 | 选择 | 理由（结合现有代码） |
|---|---|---|
| HTTP 服务形态 | **独立进程 `server_http`（新增 CMake 目标）**，端口 8080 | ① 仓库已有 header-only 库 web/httplib.h（cpp-httplib），零新依赖；② 完全不动现有 TCP:8000 Reactor 模型（client/transit 继续用）；③ 进程隔离——HTTP 崩溃不影响 TCP 在线状态；④ .env.example 注释即预期 http://127.0.0.1:8080 |
| 是否复用 Reactor | **不复用**。httplib 自带 per-connection 线程（默认线程池） | Reactor 是 \n 分帧 TCP 协议（Connection.cc），语义与 HTTP 不兼容；强行复用=重写协议解析，违背"不破坏现有稳定模型" |
| 业务代码复用 | 直接复用 MySQLPool/MySQL/Redis 封装与 Config.h | 这些类与传输层零耦合（MySQLPool.h 仅依赖 mysqlclient） |
| 新增分层 | Router → Auth → Controller → Service → DAO（新增 server/http/ 目录） | 与现有 ChatService（TCP 专用）平行，不交叉 |
| 存储 | MySQL 主存储；Redis 仅保留既有 offline_request 用途 | 契约无缓存需求；幂等用 MySQL 唯一约束（持久、重启安全） |
| 身份边界 | Bearer Token = 服务身份；用户级身份**不可信**（P8-05：BLK-1 安全阻断，待学长决策） | 前端无登录、user_id 可改；零改动约束下无法根治 |
| 并发前置 | MySQLPool::borrow 无超时（代码事实）→ S1 必须改造 borrow_for(3s)（P8-08） | 原实现池耗尽永久阻塞 |
| 启动模式自检（R11 fail-closed） | `CHATROOM_HTTP_USER_MODE` 仅接受 `p4_demo`（默认）；`multi` **未实现→启动 FATAL 退出**；未知值→FATAL；不允许任何模式绕过 P4 白名单退回存在性校验 | 配置错误不得以宽松行为运行 |
| 进程数 | server(TCP:8000) + server_http(HTTP:8080) + transit + web 并存 | 部署拓扑见 §4 |

## 3. 数据流（一次 record_meal 全链）

```
Agent urllib POST http://127.0.0.1:8080/api/v1/users/u_demo/meals
  → httplib worker 线程 → Router 匹配 POST /api/v1/users/{uid}/meals
  → Router: uid 路由正则 [A-Za-z0-9_-]{1,64}（解析失败→invalid_params，不进入后续任何层，R15）
  → Auth（顺序固定，R11）：① Bearer Token 校验 → ② **p4_demo 白名单硬判定 uid=="u_demo"（先于 UserDao）** → ③ uid 存在性（仅 multi 模式；p4_demo 不查）
  → MealController: body JSON 解析（nlohmann）→ 字段校验/默认值
  → MealService: 幂等判定
       ├─ IdempotencyDao SELECT (uid,key) 命中 → 返回首次 meal_id → 组响应
       └─ 未命中 → 事务: INSERT meal_records + INSERT idempotency_records → commit
  → 2xx JSON {ok,receipt_id,user_id,meal,source:"service"}
```

## 4. 部署拓扑

```
浏览器 ── http://host:8787 ── Agent(Python, ThreadingHTTPServer)
                                     │ 服务器到服务器（无 CORS 需求）
                                     └─ http://127.0.0.1:8080 EAT_SERVER_BASE_URL + Bearer
                                            C++ server_http（本机回环优先）
                                            │
                                            ├─ MySQL（chatroom 库，最小权限账号）
                                            └─ Redis（可选，HTTP 进程不依赖）
C++ server(TCP:8000)/transit/web —— 原有职责不变，与 server_http 并存
```

- 生产 TLS：建议 nginx 反代终止 TLS（httplib 亦可 SSLMode，但非本轮必须）。
- 8080 仅绑定 127.0.0.1（默认）或内网网卡，不直接暴露公网（Token 是唯一防线，见 P8-05）。
