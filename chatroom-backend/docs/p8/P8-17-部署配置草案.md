## 1. 配置项总表

### 1.1 P8 新增（HTTP 业务进程）

| 变量 | 默认 | 必需 | 敏感 | 说明 | 校验/失败行为 |
|---|---|---|---|---|---|
| `CHATROOM_HTTP_BIND` | `127.0.0.1` | 否 | 否 | 监听地址；生产保持回环，由 nginx 反代 | 非法 IP → 绑定失败退出 |
| `CHATROOM_HTTP_PORT` | `8080` | 否 | 否 | 监听端口 | 占用 → 启动失败退出 |
| `CHATROOM_HTTP_TOKEN` | 无 | **是** | **是** | Bearer 校验值，与 Agent `EAT_SERVER_TOKEN` 同值 | 未设置 → 启动 FATAL（fail-closed） |
| `CHATROOM_HTTP_USER_MODE` | `p4_demo` | 否 | 否 | 仅接受 `p4_demo` | `multi`/未知 → 启动 **FATAL**（R11/R20） |
| `CHATROOM_HTTP_DB_POOL` | 空 = `W=max(8,cores-1)` | 否 | 否 | 连接池大小 S，受全局预算约束（§3） | 非正整数 → 回落默认 + WARNING |
| `CHATROOM_TZ_STRICT` | `0` | 否 | 否 | 非 +08:00 时：0=WARNING，1=FATAL | 见 P8-04 §6 |
| `GLOG_log_dir` | 空（stderr） | 否 | 否 | glog 日志目录 | 目录不可写 → 启动失败 |
| `GLOG_minloglevel` | `0` | 否 | 否 | 0=INFO | — |

### 1.2 复用既有（不新增变量名）

| 变量 | 默认 | 说明 |
|---|---|---|
| `CHATROOM_MYSQL_HOST/PORT/USER/PASSWORD/DB` | 同 P7 | HTTP 进程复用同一组（同一业务库）；`DB` 在测试环境指向 `chatroom_p8` |
| `CHATROOM_PORT` / `CHATROOM_WORKER_THREADS` | 8000 / 4 | 既有 TCP 进程，**不改** |
| `CHATROOM_REDIS_*` | 同 P7 | **HTTP 进程不使用 Redis**（P8-07 §6）；保留仅为 TCP 进程 |

> 决策：不为 HTTP 进程另设 `CHATROOM_HTTP_MYSQL_*`。理由：同库同账号、避免配置双份漂移；运行期账号权限已满足新表 DML（P8-07 §8）。若未来需要读写分离，再引入独立变量（不属本轮）。

### 1.3 Agent 侧（不属于 C++ 交付物）

| 变量 | 默认 | 说明 |
|---|---|---|
| `EAT_SERVER_BASE_URL` | 空（=mock 模式） | 指向 `http://127.0.0.1:8080`；空值即回退 mock |
| `EAT_SERVER_TOKEN` | 空 | 必须与 `CHATROOM_HTTP_TOKEN` **逐字节相同** |
| `EAT_SERVICE_TIMEOUT` | `5` | Agent 单请求超时（秒），决定服务端处理预算（P8-08 §2.2 T1） |

## 2. 开发 / 测试 / 生产三档差异

| 项 | 开发（WSL 本机） | 测试（自动化） | 生产（单机内网） |
|---|---|---|---|
| 监听 | `127.0.0.1:8080` | `127.0.0.1:8080` | `127.0.0.1:8080` + nginx 反代 |
| TLS | 不启用 | 不启用 | **nginx 终止 TLS**；8080 不对外 |
| Token | 任意测试值（如 `test-token-p8`） | `test-token-p8`（固定，便于脚本） | `openssl rand -hex 32` 生成，密钥保管 |
| DB | `chatroom_s0` / `chatroom_p7` | **`chatroom_p8`（独立库）** | `chatroom`（业务库） |
| 连接池 S | 默认（空） | 默认（空，降资源占用） | 按 §3 预算计算后显式设置 |
| 时区 | `TZ=Asia/Shanghai` | 同左 | systemd `Environment=TZ=Asia/Shanghai` |
| 日志 | stderr | stderr → `evidence/p8-*.log` | `GLOG_log_dir=/var/log/chatroom` + logrotate |
| 迁移执行账号 | root（一次性） | root | root 一次性执行后立即回收（P8-07 §8） |

## 3. 连接池预算（与 P8-08 §2.1 同口径）

```
W = max(8, cores-1)                    # httplib 基础 worker（代码事实）
S = CHATROOM_HTTP_DB_POOL              # 默认空 => S = W
高压档：S = min(4W, max_connections − 8(TCP 池) − 其他服务 − 预留(>=5))
```

部署检查单（每次上线必做）：
1. `SHOW VARIABLES LIKE 'max_connections';` 记录实测值；
2. 记录 TCP 进程实际连接数（代码事实 8）；
3. 计算并写入 `.env` 的 `CHATROOM_HTTP_DB_POOL`；
4. **不引用"4W≤32 永远安全"类结论**（P8-15 R17 已废止）。

## 4. systemd 单元草案（生产，DRAFT）

```ini
# /etc/systemd/system/chatroom-http.service  （草案，未安装）
[Unit]
Description=ChatRoom HTTP Business Service (P8)
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=chatserver
WorkingDirectory=/opt/chatroom/chatroom-backend
EnvironmentFile=/etc/chatroom/http.env
Environment=TZ=Asia/Shanghai
ExecStart=/opt/chatroom/chatroom-backend/build/server_http
Restart=on-failure
RestartSec=3
# 只读根文件系统之外，仅允许写日志目录
ReadWritePaths=/var/log/chatroom
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

> 说明：`EnvironmentFile` 权限建议 `0600`、属主 `chatserver`；`.env` 不进入 Git。

## 5. 凭据与安全红线

| 红线 | 说明 |
|---|---|
| 禁止真实值入库 | 模板仅占位符 `<REPLACE_WITH_...>`；提交前敏感扫描（Token/密码/授权码零命中） |
| Token 生成 | `openssl rand -hex 32`；轮换需 Agent 与 C++ 同时更新并重启（两端不一致 → 全部 `unauthorized`） |
| Token 保管责任 | **待学长确认责任方**（P8-15 §6 第 6 问 (f)） |
| 日志禁载 | 不打印 Authorization 头、密码、摘要、明文 uid 之外的敏感信息（P8-04 §7） |
| DB 账号 | 运行期仅 DML；DDL 用 root 一次性执行后回收 |
| root 使用 | 迁移/回滚专用；不在服务单元中使用 |

## 6. 部署步骤草案（S6 交付时落地）

1. 构建：`cmake -S . -B build && cmake --build build -j`（WSL/Linux，禁止 Windows 本机编译）；
2. 备份：`mysqldump --single-transaction`（迁移前强制）；
3. 迁移：单实例执行 `001_p8_business.sql` + `foods_seed.sql`，保留 manifest 与自检输出；
4. 配置：`cp docs/p8/env.example.draft /etc/chatroom/http.env` → 填值 → `chmod 600`；
5. 启动：`systemctl start chatroom-http` → `curl /health` 断言 `{ok:true,db:true}`；
6. 联通：Agent 侧设 `EAT_SERVER_BASE_URL` + `EAT_SERVER_TOKEN` → 重启 Agent → `mode=="service"`；
7. 观察：日志无 ERROR、`/health` 稳定、P7 TCP 业务不回归；
8. 回滚预案：停服务 → 备份 → `001_p8_business_rollback.sql`（R21 校验须全通过）。
