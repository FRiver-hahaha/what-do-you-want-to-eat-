## 3. user.agent_uid 回填方案审查

| 检查项 | 结论 |
|---|---|
| 公式 | `CONCAT('legacy_', LEFT(SHA2(CONCAT(email,'#' ,id),256),16))`——**冻结口径，与 P8-05 §7/P8-12 一致；sha1 旧描述全文零残留** |
| 长度 | `legacy_`(7) + 16 hex = 23 ≤ 64 ✓ |
| 唯一性 | UNIQUE 索引；含 id 使同 email 前缀不冲突，碰撞概率 2^-64 可忽略 ✓ |
| 幂等 | `UPDATE ... WHERE agent_uid IS NULL` → 重复执行零变更 ✓ |
| 顺序风险 | 回填先于 seed：若库中已存在 `u_demo@agent.local` 且 agent_uid 为 NULL 的行，回填成 `legacy_*` → seed 预检判"email 存在但 uid 不匹配"→ **非零退出人工处理（fail-closed）** ✓；上次 seed 成功的行 agent_uid='u_demo' 非 NULL 不被回填 → same_hit=1 跳过 ✓ |
| email 长度 | email 列 VARCHAR(25)（P7 既有约束）；seed email 17 字符 ✓；回填不改 email ✓ |
| 结论 | **可靠**；建议预检脚本**先于**全部 DDL 执行（评审建议已纳入 §8 草案 Step 0） |

## 4. Seed 用户初始化方案审查

| 检查项 | 结论 |
|---|---|
| 摘要生成 | OS CSPRNG `openssl rand -hex 32`（256-bit）→ `sha256sum`（小写 hex 64 位，与 TCP `sha256()` 输出格式一致）✓ |
| 明文安全 | 明文仅存在于生成者内存/管道；不写 SQL 文件（文件只含 `@seed_pwd_hash` 变量引用）、不写日志、不进 Git；`unset` 即时销毁 ✓ |
| 会话变量 | **`SET @seed_pwd_hash` 与 INSERT 必须同一 MySQL 会话**（heredoc/单次 `--execute` 多语句）；跨连接为 NULL → 空哈希事故——已在 P8-07 §2.1 明文警示 + 模板 ✓ |
| 冲突四分支 | 都不存在→创建；同指一人→跳过；email 存在但 uid 不匹配→停；uid 存在但 email 不匹配→停；**不覆盖已有身份** ✓ |
| 重复执行 | `NOT EXISTS ×2` + 预检 → 第二遍零变更 ✓ |
| 并发迁移竞态 | 两个迁移进程同时执行：均通过 NOT EXISTS → 一方 email UNIQUE 冲突失败退出（库状态正确）。**约束：迁移单实例执行**（写入实施检查单，风险等级低） |
| TCP 登录不可达 | 密码摘要不可预测（2^256）；`state=0` 是可登录状态不是禁用（已取证）；L2.07 保留弱密码登录必须全失败 ✓ |
| 结论 | **安全**（含会话一致性事故防线与失败重试策略） |

## 5. 幂等事务方案审查（对照五条硬性要求）

| 要求 | 设计依据 | 审查结论 |
|---|---|---|
| 同 key 同 payload → 原结果 | P8-06 §4.2 快路径 + 1062 回读；payload_hash 命中 → 返回首次 receipt/meal | ✓ |
| 同 key 不同 payload → 拒绝 | hash 不同 → `idempotency_conflict`（2xx 错误体） | ✓（注意 G-9：record_meal 不检查 ok，用户仍见"已记录"文案——Agent 侧缺陷已登记，非本设计缺陷） |
| 并发只产生一条有效记录 | 唯一键阻塞串行化 + 冲突方 ROLLBACK（连带 meal 消失）→ 1 meal/1 idem | ✓（P8-08 §6 时序） |
| 失败不留孤立记录 | **先 meal 后 idem + 同事务**：idem 失败→整体回滚（meal 消失）；进程 kill→InnoDB 回滚 | ✓（P8-10 L3.33 断言设计） |
| SHA256 canonical 字段与顺序 | **R10：仅 {date,type,text}**；canonical 规范串由本轮 D-5 补齐（键字典序 date<text<type、JSON 转义、UTF-8 无 BOM/无空白/无尾换行、小写 hex SHA256） | ✓（实现期以单元测试锁定逐字节行为） |

**事务边界的两个边界情况**：
1. 快路径 SELECT 与事务之间为 TOCTOU 窗口——快路径仅优化，正确性由唯一键裁决 ✓。
2. 锁等待 `innodb_lock_wait_timeout=3`（会话级，连接池 init 时对每连接 SET）——超时 → 1205 → 事务回滚 → internal_error；幂等重试安全 ✓。

## 7. 迁移重复执行与失败恢复

**可重复机制**：① 加列 information_schema + PREPARE 条件化；② 四表 IF NOT EXISTS；③ 回填 WHERE IS NULL；④ seed 预检 + 双 NOT EXISTS + 单语句原子。

**中断状态矩阵**（重跑安全性）：

| 中断点 | 重跑行为 | 数据库状态 |
|---|---|---|
| 加列失败 | 重跑重新判定 → 再 ALTER | 无部分列（DDL 原子） |
| 建表中途失败 | IF NOT EXISTS 补建剩余表 | 已完成表保留，无半表 |
| 回填中途失败 | WHERE IS NULL 续跑 | 已回填行保留 |
| seed 失败（约束/语法） | 预检 → 分支 → 重试 | 单语句原子，无残留 |
| seed 成功但后续步骤失败 | 预检 same_hit=1 → 跳过 | 不重复 seed、不换摘要 |
| foods seed 中途 | INSERT IGNORE/ON DUPLICATE 幂等 | 固定 16 行主键幂等 |
| 人工误建 u_demo 行 | 预检判冲突 → 停止 | **人工高危重来**（备份→确认→删行），自动脚本不含删除 |

## 8. 迁移 SQL 草案（**草案，未执行**）

```sql

-- 前置：① precheck 通过（冲突即非零退出）② mysqldump 备份 ③ 单实例执行 ④ 目标库已 SELECT DATABASE() 确认

-- Step 0 预检（见 §7.1.1 预检 SQL；脚本层先执行并以退出码分支）

-- Step 1 user.agent_uid 条件化加列

             WHERE table_schema = DATABASE() AND table_name='user' AND column_name='agent_uid');
SET @sql := IF(@col = 0,
  'ALTER TABLE `user` ADD COLUMN `agent_uid` VARCHAR(64) NULL COMMENT ''Agent 侧用户标识'', ADD UNIQUE KEY `uk_agent_uid` (`agent_uid`)',
  'SELECT 1');
PREPARE stmt FROM @sql; EXECUTE stmt; DEALLOCATE PREPARE stmt;

-- Step 2 四张新表（结构以 P8-07 §2.2-2.5 为准，全部 IF NOT EXISTS）

-- meal_records（idx_uid_date）
-- idempotency_records（uk_uid_key + idx_created_at）
-- foods（id VARCHAR(64) PK）

-- Step 3 存量回填（仅 NULL；公式冻结）

   SET `agent_uid` = CONCAT('legacy_', LEFT(SHA2(CONCAT(`email`, '#', `id`), 256), 16))
 WHERE `agent_uid` IS NULL;

-- Step 4 seed 预检 → 分支（§7.1.1；不匹配 = 非零退出，人工）

-- Step 5 seed（同一 mysql 会话内执行；摘要外部注入，文件不含字面量）
--   SET @seed_pwd_hash = '<外部注入的 sha256 摘要>';
--   INSERT INTO `user` (...) SELECT ... WHERE NOT EXISTS(...) AND NOT EXISTS(...);

-- Step 6 foods seed（16 行，INSERT ... ON DUPLICATE KEY UPDATE price/available；见 foods_seed.sql 草案）

-- Step 7 自检（脚本断言）：
--   column agent_uid 存在；4 表存在；索引总数 8（4 PK + uk_agent_uid + idx_uid_date + uk_uid_key + idx_created_at；
--   按 DISTINCT CONCAT(TABLE_NAME,'.',INDEX_NAME) 计数，information_schema.STATISTICS 原始行数为 10——R23 修正）
```
