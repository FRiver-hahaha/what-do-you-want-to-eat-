## 2. R7：u_demo seed 账号密码安全

| 项 | 内容 |
|---|---|
| 原设计 | seed 密码 `SHA2('u-demo-seed',256)`，并声称"不可 TCP 登录"；隐含把 state=0 当禁用 |
| 代码取证结论 | signIn = 查 email → `sha256(输入)` 比对 → 匹配且 tryLogin（`UPDATE state=1 WHERE state=0`）成功即登录。**state=0 是"离线/可登录"，不是禁用**；`SHA2('u-demo-seed')` 是可计算哈希 → 旧方案**确实可被密码 `u-demo-seed` 登录**，旧结论错误 |
| 修订方案 | ① seed 密码改 **不可预测随机哈希**（`SHA2(CONCAT(UUID(),UUID(),RAND(),CURRENT_TIMESTAMP(6),RAND()),256)`），脚本不回显不记录；② 文档明确 state 语义；③ 不加 disabled 列（ChatService 不认，无效），以不可预测哈希为唯一手段 |
| 影响文档 | P8-07 §2.1（seed SQL + 登录语义说明）；P8-10 L2.07 |
| 验证方法 | **L2.07**：以 `u-demo-seed` 与常见弱密码经 TCP type=2 登录 `u_demo@agent.local` → 全部"密码错误" |
| 状态 | **已解决**（证据与测试落地后生效；L2.07 在 S1 执行） |
| 需学长决策 | 否 |

## 5. R10：幂等 key 与 payload_hash 一致性（唯一最终规则）

| 项 | 内容 |
|---|---|
| 原设计 | payload_hash = SHA256(完整 payload) → LLM 重试时营养估算波动会导致**同一次操作被误判为冲突**（拒绝或重复） |
| 最终规则 | **幂等身份 = (uid, idem_key)；payload_hash = SHA256(canonical{date, type, text})（仅业务身份字段，canonical JSON：键排序+UTF-8+无空格），不含 protein/fiber/veggies/water** |
| 与 Agent key 的匹配性 | Agent `key = sha1(session_id+date+type+text)[:16]` 已内含 text；服务端 hash 维度 {date,type,text} 与之完全一致 → 同一次操作（同 session/date/type/text）无论 LLM 营养估算如何变化，hash 恒同 → 返回首次结果，**不误判、不重复**；服务端不解释 key 内容，仅作复合唯一约束 |
| 用例矩阵 | ① 同 key 同 payload → 首次结果；② 同 key 不同 text → `idempotency_conflict` 拒绝；③ 同 key 同 text 不同 protein → **返回首次结果（首次营养值为权威）**；④ 不同 key 相同 payload → **两条记录**（两次真实操作）；⑤ 并发同 key → 唯一键裁决，库中 1 行，后到者返首次 |
| 影响文档 | P8-06 §4.2/§4.2.1；P8-07 §2.4；P8-02 §2.10；P8-09 流程 C；P8-10 L2.23/24/25/26 + L3.31；P8-11 S3 |
| 状态 | **已解决（规则唯一化 + 用例落地）** |
| 需学长决策 | 否 |

**新增缺口 G-11（登记，零改动不可修）**：Agent 前端 `syncLocalMeal(call.arguments)` 用**工具参数**（LLM 本次估算）同步 localStorage，而非服务端响应 `meal`（首次权威值）→ 幂等重试或 LLM 波动时，前端显示值可能与服务端权威值不同。属于 Agent/前端侧行为，不改；影响仅显示一致性（服务端统计仍以库内值为准）。
