## 2. 脚本契约（统一约定）

| 项 | 约定 |
|---|---|
| 入口 | `tests/p8/run_all.sh --base-url http://127.0.0.1:8080 --token <T> --db chatroom_p8` |
| 退出码 | `0` 全通过；`1` 存在 FAIL；`2` 环境不满足（服务未起/库不可达）；`3` 前置未授权（如多用户用例在 p4_demo 模式） |
| 环境变量 | `CHATROOM_HTTP_TOKEN` / `EAT_SERVER_TOKEN` 同值；`CHATROOM_MYSQL_DB` 指向独立库 |
| 证据 | `evidence/p8/<阶段>/<用例号>.log`（stdout+stderr 全量 tee）；断言失败附 SQL 快照 |
| 清理 | 每个用例自建自清（唯一 `agent_uid` 前缀 `t_` + 时间戳；禁止 `TRUNCATE`/批量 `DELETE`） |
| 单命令自包含 | 服务启停与用例在同一 bash 调用内完成（WSL 空闲回收会杀后台进程与会话） |
| 敏感 | 证据入库前扫描 Token/密码/摘要字面量，零命中才提交 |

## 7. 敏感与证据纪律

1. 证据文件不得包含 `Authorization` 头、Token、DB 密码、seed 明文/摘要；
2. 用例生成的数据使用 `t_<case>_<ts>` 前缀，结束后按前缀清理（逐条 DELETE，禁止 `TRUNCATE`）；
3. 断言 SQL 只读（`SELECT COUNT(*)` 等），写操作只经 HTTP 接口完成——避免测试自身绕过幂等/事务路径；
4. 失败用例保留现场（不自动清理数据），供人工复核。
