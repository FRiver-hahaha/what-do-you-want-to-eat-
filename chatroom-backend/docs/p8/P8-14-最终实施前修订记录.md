## 3. R13：u_demo 密码随机性

| 项 | 内容 |
|---|---|
| 原设计 | `SHA2(CONCAT(UUID(),UUID(),RAND(),CURRENT_TIMESTAMP(6),RAND()),256)`——`RAND()` 非密码学安全，`UUID()` v1 含时间/MAC 信息，熵不达标 |
| 修订方案 | **废止 SQL 内建随机拼接**。改为**迁移准备阶段由运维用操作系统 CSPRNG**：`openssl rand -hex 32`（256-bit）生成明文（仅内存/管道）→ `sha256sum` 计算摘要（小写 hex 64 位，与现有 TCP 登录 `sha256()` 输出格式一致）→ 仅摘要以变量传入 INSERT；**明文不写 SQL 文件、不写日志、不进 Git，用后即销毁**；**TCP 登录代码零改动**；L2.07 保留。 |
| 影响文档 | P8-07 §2.1（seed 流程注释 + 说明）、P8-10 L2.07 标注 |
| 验证方法 | L2.07 弱密码登录全部失败；迁移脚本人工核查"无明文落盘"（SQL 文件内仅变量引用）；摘要长度/格式断言 |
| 状态 | **已解决** |
| 需学长决策 | 否 |

## 4. R14：MySQL 连接池容量公式

| 项 | 内容 |
|---|---|
| 原设计 | "高压档 S=4W（≤32），MySQL max_connections 151 下 8 核→32 连接，安全"——把特定环境的数值当通用结论 |
| 修订方案 | **删除"4W≤32 永远安全"结论**。明确：W=max(8,cores−1)；峰值 worker ≤4W；**S 由配置 `CHATROOM_HTTP_DB_POOL` 决定**，且受四类约束共同限定：① MySQL `max_connections`（部署实测）② TCP 既有池 8（代码事实）③ 其他服务连接 ④ 运维预留（建议≥5）；**默认 S=W 为初始值**；高压档必须按实际预算计算（S = min(4W, max_connections−8−其他−预留)）；**明确不承诺所有 worker 能同时拿到连接**（borrow_for 3s + db busy 是设计的一部分）。 |
| 影响文档 | P8-08 §2.1 |
| 验证方法 | S3 压测记录实际并发与连接数（M-4/M-3）；部署文档要求先查 max_connections |
| 状态 | **已解决** |
| 需学长决策 | 否 |

## 5. R15：路由 UID 正则统一

| 项 | 内容 |
|---|---|
| 原设计 | P8-05 用 `^[A-Za-z0-9_\-]{1,64}$`（转义连字符），P8-04 路由示例用 `(\w+)`（不允许连字符，且 `\w` 依赖 locale）——两处不一致且路由层会拒绝合法连字符 uid |
| 修订方案 | **统一为 `[A-Za-z0-9_-]{1,64}`**（连字符置于字符类末尾，无需转义，语义明确允许连字符）；**Router 与 Auth 双处校验**；任何路径解析失败一律 `invalid_params` 直接返回，**不进入 UserDao 及任何 Controller**。 |
| 影响文档 | P8-04（Router 生命周期）、P8-05 §3-B、P8-09 流程 A、P8-10 L2.09 |
| 验证方法 | **L2.09**：`a-b_c9` 合法通过；含 `/`、空格、65 字符 → invalid_params 且 Controller 零调用（日志佐证） |
