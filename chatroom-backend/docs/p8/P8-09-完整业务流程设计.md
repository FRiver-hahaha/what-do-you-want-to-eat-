## 流程 B：更新健康档案（闭环）

```

  → PATCH /api/v1/users/{uid}/health-profile（uid 必须已存在）

```
**闭环状态：完整**（含 Agent 侧 ok 校验）。

## 流程 C：记录饮食（幂等全链，R2 修订）

```
用户: "午饭吃了柠檬鸡胸能量碗和无糖茶"
  → LLM record_meal → idempotency_key = sha1(session:date:type:text)[:16]
  → POST /api/v1/users/{uid}/meals（uid 必须已存在）
  → MealController: 默认补齐(date→今天本地时区, time→现在, penalty→服务端正则补算, items 空→[text])
  → MealService 幂等（P8-06 §4.2）:
       hash = sha256(canonical {date,type,text})   # R10：仅业务身份字段，营养重估不判冲突
       快路径 SELECT idem(uid,key): 命中 → hash 同→首次结果 / 异→idempotency_conflict
       未命中 → BEGIN
                  INSERT meal_records → @meal_id
                  INSERT idempotency_records(uid,key,hash,@meal_id)   ← 唯一冲突即回滚
                COMMIT
       并发 1062 → ROLLBACK（连带 meal 消失）→ 回读已提交 → hash 同→首次结果 / 异→conflict
  → 响应 {ok, receipt_id=yyyyMMdd-HHmmss-meal_id, meal{...time,penalty}, source}
  → Agent: **不检查 ok（G-9）** → 用户总看到"已记录"文案（服务端失败时误导，阻断登记）
  → 前端 syncLocalMeal(call.arguments) → 时间线渲染
  → 验证环: get_recent_meals → GET ?days=1 → 含新记录；幂等重放 → 同 receipt、库 1 行
  → 重启后重放 → 仍同 receipt（TABLE 持久）
```
**闭环状态：服务端完整（幂等/事务/重启安全）；Agent 反馈语义有缺陷（G-9，阻断待决策）**。

## 流程 D：删除/修改饮食（R3 定性：**不闭环，登记阻断**）

```
用户: "把下午茶删了" / "午餐改成牛肉面"
  → LLM delete_meal / update_meal
  → 工具直接返回 {meal_action:{action:...}, source:"frontend"}（**不产生任何 HTTP 请求**）
  → SSE tool_result → 前端 app.js:628 applyMealAction → 仅改 localStorage
  → 服务端: 无接口调用、无 SQL、记录不变
```
| 维度 | 事实 |
|---|---|
| Agent 已实现 | 添加（走服务端）/ 读取（走服务端）/ 删改（**纯前端动作**） |
| ServiceClient 现有接口 | 10 个，**无** meals/{id} 的 PATCH/DELETE 方法 |
| C++ 本轮允许实现 | 仅 10 个契约接口——**不新增删改接口**（无调用方，加了也不闭环） |
| 无法闭环部分 | 服务端记录永不删改；统计（gap/weekly/ranking）把"已删"记录算在内 |
| 需要学长授权的改动 | ① Agent：delete_meal/update_meal 改调 ServiceClient（新增方法）；② Agent 需获得 meal_id（record_meal 响应已有 meal 但前端不持有——需前端透传或按 date+type+text 定位）；③ 前端配合（可能不改，若 Agent 按定位删） |
**闭环状态：不闭环。禁止宣称"删改功能完成"（P8-12 BLK-2）。**

## 流程 E：营养缺口与每周统计（R4 修订：公式复刻 + 数据来源声明）

```
nutrition-gap?date=D:
  intake = SUM(protein,fiber,veggies,water) FROM meal_records WHERE uid AND date=D
  targets = {protein:90, fiber:25, veggies:500, water: health_profile.water_target|1800}
  gap = max(0, target-intake)
weekly-stats:
  rows = meal_records WHERE uid AND date ∈ [本周一, 今天]
  days_recorded   = COUNT(DISTINCT date)
  three_meal_days = COUNT(DISTINCT date WHERE types ⊇ {早,午,晚})
  points          = Σ每日(早/午/晚各10 + 齐全+20)          ← app.js getMealPoints 同口径
  avg_health_score= AVG(逐日 score)，公式 **严格复刻前端**：
      score_day = clamp(45,96, round(68
                  + min(intake.veggies/500,1)*8
                  + min(intake.protein/90,1)*6
                  + min(intake.fiber/25,1)*5
                  + min(meal_count,3)
                  + activityBonus(较高3/适中2/其他0)
                  - penalty_sum_day))
  streak = 连续记录日数（自今天或最近记录日回溯）
```
**输入来源声明（R4 诚实结论）**：
- intake/penalty 来自 meal_records：protein 等为 **Agent payload 值（LLM 从用户描述估算）**；penalty 为 **服务端正则补算**（P8-06 §7.5）。与前端 analyzeMealText 正则估算的数值可能不同 → 同一公式两端结果可能不同。
- 服务端承诺：**公式同源 + 输入以服务端落库为准**；不承诺与浏览器实时分数逐分一致（前端用本地数据本地算，契约禁改前端）。
**闭环状态：完整**（可手工复核；L2.34 用例对照公式）。
